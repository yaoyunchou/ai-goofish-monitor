# PRD：账号按渠道分开（增量）

> **交付状态**：本期实现  
> **提出日期**：2026-09-24  
> **类型**：简单增量 PRD（无竞品分析）  
> **对应设计**：`docs/design/account-channels.md`

## 1. 项目信息

| 项 | 内容 |
|----|------|
| 项目 | `ai_goofish_monitor` |
| 语言 | 中文 |
| 变更性质 | 账号索引增加渠道。Cookie 仍在文件里，不进数据库 |

### 1.1 原始需求复述

账号页现在把 `state/*.json` 都当成闲鱼登录态。小红书笔记必须登录，不能和闲鱼混用同一份状态文件。需要能按渠道区分闲鱼和小红书账号，已有文件保持闲鱼行为不变。

## 2. 产品定义

### 2.1 目标

1. 每个账号标明 `goofish` 或 `xhs`。
2. 已有 `state/*.json`（不含子目录）登记为闲鱼，不移动、不改写文件。
3. 闲鱼任务选账号时只看到闲鱼。笔记只使用已启用的小红书账号。
4. 本期不做多账号轮换。笔记设置里选定一个小红书账号。

### 2.2 用户故事

1. 作为运营者，我希望新建账号时选择闲鱼或小红书，避免把小红书登录态拿去跑闲鱼任务。
2. 作为运营者，我希望原来的闲鱼账号还能用来建任务，不用重新登录。
3. 作为运营者，我希望停用某个小红书账号后，笔记定时不会再选它。

## 3. 范围

- 表 `monitor_accounts`：渠道、名称、相对 `state/` 的文件名、是否启用、最近检查时间、最近错误。
- 同一渠道内名称唯一。两个渠道可以同名，文件路径不能相同。小红书文件放 `state/xhs/`，闲鱼继续放 `state/` 根目录。
- 列表可按渠道筛选。不传渠道则返回全部，并带渠道字段。
- 新建缺省渠道是闲鱼。删除同时删文件和表行。

不在本期：账号轮换、把 Cookie 正文写入数据库、改变闲鱼采集。

## 4. 验收

1. 旧的 `state/*.json` 登记为 `goofish`，文件内容不变。
2. 新建的小红书账号不会出现在闲鱼任务的账号列表里。
3. 停用的小红书账号不能被笔记定时选中。
