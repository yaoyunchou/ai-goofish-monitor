### 1.1 需求复述

用户打开店铺数据页，期望看到**已经采回来的卖家订阅数据**（想要 / 浏览、店与商品规模）。现状却是「店铺数据罗盘」空状态，文案要求去跑卖家工作台 datacompass。用户并没有罗盘任务和快照，真正在跑的是 C 端卖家订阅采集，库里已有约一天半的日指标。页面同时是原型骨架（硬编码指标卡、`<ul>` 分布、纯文字 `showPv`），即使将来有罗盘数据也「看起来假」。

本期要把 `/shop-analytics` 做成**订阅采集数据的跨店分析看板**：有一天数据就要立刻看出规模、热度、店间对比；没有订阅日指标时才空，并引导去采集控制台。

## 2. 产品定义

### 2.1 Product Goals（3 个正交目标）

| ID | 目标 | 说明 |
|----|------|------|
| G1 | **有数即显** | 只要 `seller_item_daily_metrics` 有行，打开 `/shop-analytics` 就展示真实汇总；禁止再用「请先跑罗盘任务」挡住主界面。 |
| G2 | **像分析页** | 主界面必须是：数字卡片 + **至少一张真实趋势图** + 店铺排行表。禁止纯文字 `showPv` 列表、禁止硬编码罗盘指标、禁止假 demo 数据。 |
| G3 | **口径诚实** | 只展示订阅采集真实有的字段（想要 / 浏览 / 监控商品数 / 店数）。不编造曝光、支付、UV、点击率等 datacompass 指标；监控商品 ≠ 闲鱼店铺商品总数。 |

### 2.2 User Stories

1. **As a** 运营，**I want** 打开「店铺数据」就能看到今天采了几家店、多少商品、想要和浏览合计，**so that** 我不用再猜采集有没有产出。
2. **As a** 运营，**I want** 一张按日的想要/浏览趋势图（近 7 天缺日就空心），**so that** 哪怕只有一两天数据，看起来也是看板而不是占位稿。
3. **As a** 运营，**I want** 按浏览给订阅店排行（当前库应是笑笑书馆明显高于妮吧啦啦），**so that** 我能立刻做店间对比。
4. **As a** 运营，**I want** 从排行点进已有卖家详情、从热门商品点进已有商品详情，**so that** 分析页能接到现有下钻，而不是死胡同。
5. **As a** 尚未跑通订阅采集的用户，**I want** 空状态明确引导我去「卖家订阅 / 采集控制台」，**so that** 我不会被要求去配我根本没有的工作台罗盘任务。

## 3. 产品决策（本期锁定）

1. **`/shop-analytics` 的主数据源改为卖家订阅采集**，读 `seller_item_daily_metrics` + `seller_subscriptions` + `seller_profiles`（店名用画像 `nickname`）。不把 datacompass 硬揉进主看板。
2. **侧栏名称可仍叫「店铺数据」**；页内标题从「店铺数据罗盘」改为「店铺分析」（或同等「订阅店铺看板」），副文案改为「基于卖家订阅采集的想要 / 浏览日指标」，去掉 datacompass / 工作台表述。
3. **周期**：默认 **今天（Asia/Shanghai 日历日）**；可切换 **近 7 天**。不再默认 1d / 7d / 30d 的 datacompass `time_cycle`。30 天周期本期不做。
4. **旧 `/api/shop-analytics/*`**：无快照时可保留空实现或降为次要入口；**主页面不得再以罗盘空消息作为主状态**。页面主路径禁止再调「无快照就引导跑罗盘」的 overview 作为唯一数据源。
5. **本页「立即采集」不得再触发 `shop_datacompass`。** 改为「刷新」+ 链到 `/seller-subscriptions/collection`（是否顺带 `POST /api/seller-subscriptions/run` 见待确认，默认不做）。
6. **不做**：AI 解读、假 demo 数据、把工作台曝光/支付等指标填进卡片。

## 4. 技术规范

### 4.1 数据口径（必须写进 UI 注释或卡片 tooltip）

与策略 SSOT §5.4 一致：

| 指标 | 定义 | 禁止 |
|------|------|------|
| 订阅店数 | `seller_subscriptions` 中 **enabled=true** 的卖家数 | 不要用闲鱼主页粉丝/商品总数冒充 |
| 今日有数据店数 | 当天 `seller_item_daily_metrics` 去重 `seller_user_id` | — |
| 监控商品 / 今日已采商品数 | 指定 `snapshot_day` 下 **去重 `item_id`** | **不是** `seller_profiles.item_count`，也不是闲鱼店铺「在售/已售商品数」 |
| 想要合计 | 指定日 `SUM(want_count)` | 不是曝光、不是 UV |
| 浏览合计 | 指定日 `SUM(view_count)` | 不是工作台 `showPv` / `ipv` |
| 全库去重商品 | `list_latest_item_metrics` 那种跨日 DISTINCT（当前 185） | **不要**当作「今日已采」；今日应为 **181** |

**空状态判定（P0）**：`seller_item_daily_metrics` **0 行** 时才进入空状态。有订阅但还没入库日指标，同样走空状态，文案引导采集，不引导罗盘。有 ≥1 行日指标，即使罗盘表为 0，也必须进有数界面。

### 4.2 周期行为

| 模式 | 卡片与排行 | 趋势图 |
|------|------------|--------|
| 今天（默认） | 全部按上海日历 **当天** `snapshot_day` 聚合 | 见下方默认假设 |
| 近 7 天 | 排行与「想要/浏览卡片」取 **区间内最新有数据日**（并标明该日期），避免把多天快照的想要/浏览直接相加当成流量；店数/商品数为区间内去重 | 横轴 7 个上海日历日；**无数据日空心**（断线或空柱），有几天画几天 |

当前库只有 9/16、9/17 两天：近 7 天图应出现 **2 个实心点 + 5 个空心日**，不得把缺日补成 0 冒充「没人看」。
