# 闲鱼周差值与小红书高水位：算法对比

> 日期：2026-09-22  
> 用途：决定以后要不要把闲鱼「想要 / 浏览」改成同一套变化算法。  
> 本期结论：小红书菜单使用高水位；闲鱼日指标与健康度周差值不改。

两边记的都是累计数。闲鱼是「想要 / 浏览」，小红书是「累计已售」。比的是变化怎么算，不是指标名字。

## 闲鱼现在怎么算

代码在 `src/services/seller_item_daily_storage.py`。

- 同一商品、同一上海日只留一行。当天再采，直接覆盖 `want_count` / `view_count`。上午、中午的数不留。
- 周增长 = 这一周最后一天的数 − 第一天的数（`weekly_item_growth_sync`）。中间几天的起伏不参与。
- 新读数变小会盖掉当天的数，周差值可以变成负数。
- 周 SQL 用 `COALESCE(值, 0)`。缺数会被当成 0，看起来像真的涨了或跌了。
- 商品页画的是累计想要/浏览，没有「今日 +N」「上小时 +N」。

适合回答「这周有没有动」，用来决定要不要停监控。不适合回答「今天几点在涨」。

## 小红书现在怎么算

源口径在 hsld `red-potato-radar/analytics.py` 的 `high_water` / `delta_between`。本仓库实现在 `src/domain/xhs_analytics.py`。

- 每次采集追加一条快照。原项目同一整点会 REPLACE；本仓库整点内也追加，便于核对坏读数。
- 高水位 = 截至该时刻历史累计的最大值。新读数更小就忽略，不把水位拉低。
- 今日 = 现在的高水位 − 今日 00:00 的高水位。
- 昨日 = 今日 00:00 的高水位 − 昨日 00:00 的高水位。0 点那条只做分界，不会两天各算一次。
- 上小时、某日每个整点 = 相邻整点高水位相减。
- 没有起点时结果是空（界面「—」），不写成 0。当天中途才开始盯，用当天第一条真实快照当起点，并标「口径不完整」。

## 案例 1：同一天采了三次

真实浏览：昨天 23:00 为 980。今天 09:00 为 1000，12:00 为 1080，16:00 为 1200。

闲鱼当天只留 16:00 的 1200。库里看不到 +80 和 +120。若用相邻两日的日值相减，只能得到 1200 − 980 = 220，分不出上午和下午。

小红书留下多条快照。若昨天 23:00 的高水位是 980：

- 今日 = 1200 − 980 = 220
- 9 点到 12 点 = 80，12 点到 16 点 = 120

若今天 09:00 才开始盯、没有 00:00 基线：用 09:00 的 1000 做起点，今日 = 200，并标「口径不完整」（09:00 之前的涨幅不算）。闲鱼没有这句说明，会把 1200 当成今天的存量。

## 案例 2：下午读数坏了（解析成 80）

真实序列：周一 500，周二 09:00 为 600，周二 16:00 坏读数 80，周三 700。

闲鱼周二被覆盖成 80。

- 若周增长的终点停在周二：增长 = 80 − 500 = −420（假跌）。
- 周三采到 700：若仍用「周末 − 周初」且周三是终点，增长 = 700 − 500 = 200，坏点被跳过，周数字碰巧还对。
- 但周二这一行永远是 80。按日看曲线会先掉到 80 再跳到 700，周三看起来暴涨 +620。

小红书高水位：80 小于已有的 600，忽略。周二高水位仍是 600，周三是 700。不会出现 −420，也不会在周三制造 +620。

## 案例 3：缺数被当成 0

窗口第一天想要是空，最后一天想要是 10。

闲鱼周 SQL：`COALESCE(空, 0)`，增长 = 10 − 0 = 10。这 10 可能是第一天没解析到，不是真的涨了 10。

小红书：起点高水位是空，增量就是空，界面「—」。

闲鱼单日只有一行时，周函数会丢掉（首尾必须不是同一天）。空变 0 出在跨天且某一端是 NULL。

## 案例 4：0 点归属

昨天 16:00 已售 990，今天 00:00 已售 1000，今天 10:00 已售 1030。

小红书：昨日算到今天 00:00 为止（+10 算昨天），今日 = 1030 − 1000 = 30。同一条 00:00 不进两天。

闲鱼按采集时刻的上海日期落日。00:00 这条算今天，昨天停在 990。日值相减是 1030 − 990 = 40，凌晨那 10 和上午那 30 糊在一起。

## 案例 5：想要先涨后掉

09:00 想要 100，12:00 想要 180，16:00 想要 110（有人取消想要）。浏览和已售一般只增不减，想要可以减。

闲鱼当天只留 110。峰值 180 丢了，但「现在是 110」是对的。

小红书高水位停在 180。今日增量按 180 算，16:00 的回落被藏住。拿来算已售是对的。拿来算想要会偏高，看不到回落。

所以：

- 浏览、累计已售：单调累计。高水位更合理，以后可以统一。
- 想要：可能下降。高水位会藏回落；首尾相减能看到净变化，但会被坏读数带歪。
- 统一之前要先定：想要要「净变化」还是「历史最高增量」。不能三个指标无脑套同一个 MAX。

## 结论

- 看每个商品怎么变：小红书高水位更合理。案例 1、2、4 都是闲鱼看不出来或算错。
- 闲鱼周首尾差适合「这周动没动」这种粗筛。坏点只要不是窗口终点，周数字还能蒙对，但当天曲线是错的。
- 空当 0：闲鱼周 SQL 不合理。以后即使不统一算法，也该改成空就是空。
- 真要统一：必须先把闲鱼从「一日一行覆盖」改成「快照追加」。只改减法公式、存储仍覆盖，日内变化还是没了。本期不做这件事。
